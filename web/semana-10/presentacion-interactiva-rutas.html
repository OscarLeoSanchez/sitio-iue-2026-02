01

Qué es un servidor

¿Quién contesta cuando escribes una dirección en el navegador?

El problema

Una página no aparece sola

Cuando abres una página, alguien tiene que entregártela.

Tu navegador es el cliente: el que pide. Un servidor es un programa que se queda esperando y contesta lo que le piden.

Hoy escribes ese programa. Tu servidor va a responder texto, datos, páginas y archivos.

Modelo mental

Una petición, una respuesta

PeticiónLo que el navegador pide
Un mensaje con un método, como GET, y una ruta, como /.
El pedido que le dices al mesero.
GET /
Creer que el servidor empieza. Siempre empieza el cliente.
RespuestaLo que el servidor devuelve
Un estado (200, 404), un tipo de contenido y un cuerpo.
El plato que sale de la cocina.
200 OK con el texto Hello World!
Tomar un 404 por una falla del servidor.

Simulación

Las partes de una dirección

localhostEl nombre de tu propio computador
Quiere decir "esta máquina". El navegador y el servidor corren en el mismo computador.
Creer que necesitas internet para abrirlo.
PuertoLa puerta por la que atiende el programa
Un número. Un computador tiene muchas puertas y cada programa atiende en una.
El número del local en un centro comercial.
RutaQué se pide dentro del servidor
Lo que va después del puerto y empieza con /. La ruta / es la raíz.
/saludo

    La función de la ruta se ejecuta en cada petición, así que DateTime.Now da la hora de ese momento. /saludo no calcula nada y responde siempre igual.

    Datos en la dirección

    ¿Cómo recibe tu servidor un dato que cambia en cada petición, como un nombre o el número de un producto?

    Etapa 2

    Un dato que viaja en la ruta

    Parámetro de la rutaLa parte que cambia entre llaves
    Lo que va entre llaves en la ruta llega a la función en un argumento con el mismo nombre.
    Un formulario con un espacio en blanco que se llena con lo que escribe quien pide.
    Escribir {nombre} en la ruta y (string name) en la función: los nombres deben coincidir.
    Tildes en la direcciónMaría viaja como Mar%C3%ADa
    Las direcciones solo admiten ciertos caracteres. El navegador codifica la tilde y el servidor la decodifica: la respuesta sale con María.

    Etapa 2

    Cuando el dato debe ser un número

    Pides /producto/tomate. ¿Qué responde?

    404. Con la restricción :int, tomate no encaja en la ruta. Para el servidor esa dirección no existe, y la respuesta llega vacía.

    Etapa 2

    Datos extra después del ?

    Ruta o query stringCuándo usar cada uno
    La ruta identifica qué pides: /producto/7. El query string ajusta cómo lo pides o qué buscas: ?q=tomate.
    /buscar?q=tomate&q=papa
    string? y ??Cuando el dato puede no venir
    string? admite que q no llegue. q ?? "todo" usa "todo" solo si q no llegó.
    /buscar?q= trae q vacío, no ausente: responde Buscando: y no todo.

    Resumen de la etapa 2

    Lo que respondió cada dirección

    DirecciónRuta que la atiendeRespuesta
    /saludo/Maria/saludo/{nombre}200 Hola, Maria. Bienvenido a la plaza
    /producto/7/producto/{id:int}200 Producto número 7
    /producto/tomateninguna404 vacía
    /vendedor/rosa/vendedor/{nombre}200 Vendedor: rosa
    /buscar?q=tomate/buscar200 Buscando: tomate
    /sumar/3/4/sumar/{a:int}/{b:int}200 3 + 4 = 7

    Datos en JSON

    ¿Cómo le entregas datos con forma a otro programa, y ya no solo texto para leer?

    Simulación

    El mismo producto, en JSON

    Cambia los datos del producto

    En C# las propiedades empiezan con mayúscula (Id). En el JSON que sale quedan en minúscula (id).

    Lo que sale del servidor

    {"id":1,"nombre":"Tomate","precio":3500}
    JSONTexto con forma para que lo lean programas
    Un formato de texto con pares "clave": valor entre llaves, y listas entre corchetes.
    Una ficha de producto con casillas rotuladas: id, nombre, precio.
    Las claves y los textos llevan comillas dobles. Las comillas simples no valen.
    recordUna clase corta, solo para datos
    Declara en una línea un tipo con sus propiedades. new(1, "Tomate", 3500m) crea un producto.

    Etapa 3

    Devuelves una lista y sale JSON

    Lista en memoriaLos datos viven mientras el programa corre
    List guarda varios productos en la memoria del programa. Al detenerlo, los cambios se pierden.

    Etapa 3

    Un producto por su número

    FirstOrDefault y is nullBuscar y revisar si apareció
    FirstOrDefault devuelve el primer producto que cumple la condición, o null si no hay ninguno. is null pregunta si no apareció.
    Usar el producto sin revisar si es null: el programa falla al leer sus propiedades.

    Etapa 4

    Una carpeta pública de archivos

    wwwrootLa carpeta que el servidor entrega tal cual
    Todo lo que pones ahí se puede pedir con su nombre. El servidor no ejecuta nada: lo lee y lo envía.
    Una vitrina: lo que está adentro lo ve cualquiera que pase.
    Dejar ahí archivos que no quieres publicar.
    Tipo de contenido por extensiónEl servidor lo deduce del nombre
    index.html sale como text/html y estilos.css como text/css.

    Etapa 4

    La página pide sus propios datos

    const lista = document.getElementById("lista");

fetch("/api/productos")
    .then(respuesta => respuesta.json())
    .then(productos => {
        lista.innerHTML = "";

        productos.forEach(producto => {
            const item = document.createElement("li");
            const precio = producto.precio.toLocaleString("es-CO");
            item.textContent = producto.nombre + ": $" + precio;
            lista.appendChild(item);
        });
    })
    .catch(() => {
        lista.innerHTML = "<li>No se pudo cargar la lista</li>";
    });

    Etapa 4

    Dos respuestas para la misma dirección

    Dejas el MapGet("/") de antes, escrito después de UseStaticFiles(). ¿Qué ves en /?

    Ves el texto del MapGet: la ruta gana al archivo. /index.html sí entrega la página. Por eso la etapa 4 quita el MapGet("/").

    Mira el prompt antes de ejecutar dotnet new y entra a tu carpeta de proyectos con cd.

    Esperar un 400 con :intUn texto en lugar del número da 404 vacío
