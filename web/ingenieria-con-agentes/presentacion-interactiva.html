Plaza es una aplicación ASP.NET Core MVC (.NET 10) con EF Core y PostgreSQL. Hoy permite ver el catálogo (`/catalogo`), ver un producto (`/catalogo/{id}`) y pedir un solo producto (`/catalogo/{id}/pedir`). Se necesita un carrito en `/carrito` para pedir varios productos en un solo pedido.

## Reglas

- R1. `Producto` gana los campos `Stock` (entero) y `EsOrganico` (booleano), con una migración de EF Core y estos datos iniciales: Tomate, stock 20, orgánico; Aguacate, stock 15, orgánico; Papa, stock 50, no orgánico; Panela, stock 30, no orgánico.
- R2. En `/carrito`, cada producto del catálogo se muestra con su precio, su stock, si es orgánico y un campo de cantidad. La cantidad es un entero entre 0 y el stock del producto. Si no lo es, se muestra "La cantidad de {producto} debe estar entre 0 y {stock}", por ejemplo "La cantidad de Tomate debe estar entre 0 y 20".
- R3. Subtotal = suma de precio por cantidad de cada producto.
- R4. Descuento del 10% del subtotal si el subtotal es de 50.000 COP o más.
- R5. Domicilio de 5.000 COP. Es gratis si el subtotal es de 80.000 COP o más. Total = subtotal menos descuento más domicilio.
- R6. No se confirma el pedido si todas las cantidades son 0 (se muestra "Agrega al menos un producto") ni si el nombre del cliente no cumple la regla del pedido actual (entre 3 y 60 letras, obligatorio).
- R7. Al confirmar, se muestra una página de gracias con el resumen: cada producto con su cantidad, el subtotal, el descuento, el domicilio, el total y el número de pedido.
- R8. El pedido de un solo producto que ya existe (`/catalogo/{id}/pedir`) sigue funcionando igual.

# Registro del ciclo autónomo con autoauditoría

Criterios de parada: R1 a R8 comprobadas con evidencia, compilación sin advertencias nuevas y una auditoría sin hallazgos, o 5 vueltas. Base de comparación: `dotnet build` del commit base compila con 0 advertencias.
**Auditar.** Hallazgos:
1. El enlace del catálogo al carrito era un `href="/carrito"` escrito a mano; el resto de las vistas usa tag helpers (`asp-controller`, `asp-action`), así que se rompería si cambia la ruta.
2. Ninguna prueba cubría ese enlace.
3. Sin evidencia todavía de que R8 se comporte igual que en el commit base (solo comprobé que responde); falta una comparación diferencial.
4. Sin evidencia de que el modelo y la migración estén sincronizados (`has-pending-model-changes`).
5. Decisión a documentar: la numeración compartida cambia cómo se numeran los pedidos de un producto si antes hubo pedidos del carrito (1, 3, 4 en lugar de 1, 2, 3); sin carritos es idéntica.
**Auditar.** Hallazgos:
1. Los casos esperados los calculé yo a mano y yo escogí las combinaciones: puede haber un sesgo compartido entre el código y la prueba. Falta una verificación independiente que barra combinaciones.

# Plaza

Tienda de mercado campesino en ASP.NET Core MVC (.NET 10) con EF Core y PostgreSQL. Aún no tiene proyecto de pruebas.

## Comandos

- Compilar: `dotnet build`
- Correr: `dotnet run --launch-profile http` (http://localhost:5138/catalogo)
- Listar migraciones: `dotnet ef migrations list`
- Crear migración: `dotnet ef migrations add NombreEnPascalCase`
- Aplicar migraciones: `dotnet ef database update`
- Requiere PostgreSQL en localhost:5432 y `dotnet-ef` (`dotnet tool install --global dotnet-ef`)
## Convenciones del código existente

- Clases, métodos y mensajes en español; sin `namespace`
- Controladores en `Controllers/` con rutas por atributo, por ejemplo `[HttpGet("catalogo/{id:int:min(1)}")]`
- Cada servicio tiene una interfaz y una clase en `Services/` (`ICatalogo`, `CatalogoEf`); el controlador no usa `DbContext`
- Dependencias por constructor, en un campo `private readonly` sin guion bajo
- Entidades en `Models/`; el modelo de EF y los datos iniciales (`HasData`) viven en `Data/PlazaDbContext.cs`

## No tocar

- Las migraciones ya creadas ni `PlazaDbContextModelSnapshot.cs` (se generan con `dotnet ef`)
- `appsettings.Development.json` y cualquier `.env`
- `bin/` y `obj/`

## Terminado significa

- `dotnet build` sin errores
- Si cambió el modelo, existe una migración nueva y aparece en `dotnet ef migrations list`
